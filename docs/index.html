01 — WHY NUCLEUS

Safer abstractions.
Native performance.

Nucleus wraps the CUDA Runtime API without hiding how the GPU works. You keep explicit control while the type system handles the sharp edges.

01

Typed device pointers

dev::Ptr<T>, Ptr2<T>, and Ptr3<T> preserve element types and dimensional intent from host code all the way into kernels.

dev::Ptr<const float>compile-time checked
02

RAII everywhere

Memory, streams, events, textures, surfaces, and graphs clean themselves up deterministically.

03

Fluent stream API

Chain launches, copies, fills, callbacks, and synchronization into readable execution flows.

04
CU

CUDA header isolation

Host-side translation units use clean Nucleus headers without pulling CUDA headers into every consumer. Keep builds lean and toolchains predictable.

02 — QUICK START

From clone to kernel in minutes.

Nucleus builds with CMake and works as a standalone library or an embedded submodule.

01

CUDA Toolkit11.0 or newer

02

CMake3.18 or newer

03

C++ compilerC++20 support

powershell / bash 
$ git clone https://github.com/WenchaoHuang/Nucleus.git
$ cd Nucleus
$ cmake -B build -DNUCLEUS_BUILD_SHARED_LIB=ON
$ cmake --build build --config Release
✓ Ready to link nucleus
$ git submodule add https://github.com/WenchaoHuang/Nucleus.git third_party/nucleus

# CMakeLists.txt
add_subdirectory(third_party/nucleus)
target_link_libraries(my_app PRIVATE nucleus)
✓ Embedded in your build tree
